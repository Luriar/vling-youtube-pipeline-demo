# 설계 및 데이터 보호 원칙

이 문서는 실제 코드가 아닌 공개용 요약입니다. 서비스 계정, 클라이언트 식별자, 내부 URL, DB 접속정보, 스크래핑 선택자와 회사 원본 파일을 담지 않습니다.

## 업무 흐름

외부 채널 분석(Vling) → 채널 데이터 정규화 → DB 저장 및 기존 수동 주석 보존 → YouTube 영상과 Shorts 추가 수집 → 영상 DB 적재 → Flask 조회와 입력. 공개 데모는 가상 데이터로 채널/영상 적재와 주석 보존만 재현합니다.

## 실무 경험과 데모의 차이

- **실무 경험:** Vling의 채널 및 시청자 분석 데이터를 수집하여 MySQL에 저장 또는 갱신하는 기능을 구현했습니다.
- **예시 구현:** 완전히 가상의 채널과 영상 데이터를 SQLite에 적재하고, 갱신 시 사람이 쓴 메모를 보존하는 독립 예제입니다. 네트워크 수집은 없습니다.
- **비공개:** 회사 업무 시스템에 종속된 세부 구현, 고객 및 사용자 데이터, 계약/운영 정보
- **미확정 항목:** 미측정 성능 개선률, 세부 배포 이력, 회사 측 승인 범위

## 개선 및 품질 관점

실무에서 발생했던 데이터 중복, 오류 추적, 관리 편의성과 수동 확인의 필요성 같은 문제를 일반화하여 설명합니다. 수치와 성과는 확인된 근거가 없는 경우 기재하지 않습니다.
